# Publishing the apps

Everything the user does to put TAKIP on Google Play and the App Store, sign the desktop apps, and
offer the files on takip.dev/download. How the apps work: [`../architecture/native-apps.md`](../architecture/native-apps.md).
Steps marked **(once)** are one-time setup; §6 is the routine for each release.

A release is needed only when a shell changes (`apps/mobile`, `apps/desktop`). Site changes reach
every app with the next web deploy.

## 0. Before either store

- **The name on the listing.** Both stores show the developer's name. An individual Apple account
  shows your legal name as the seller. To keep a person's name off the listing (the site names none),
  enroll as an organization, which needs a legal entity and a free D-U-N-S number
  (developer.apple.com/support/D-U-N-S). Google Play lets you choose the developer name.
- **EU trader status (DSA).** Both stores ask whether you are a trader. A trader's address, phone and
  email are shown on the listing in the EU. If TAKIP earns money (ads on the site, paid plans), the
  honest answer is likely yes. The alternative is to leave the EU out of the app's countries.
- **Privacy answers** (Play's Data safety and Apple's App Privacy) follow takip.dev/privacy. With an
  account: email address and name, user id. Without one: a random visitor id, usage of features
  (minute ticks, page views), and an approximate place from the IP address, used for statistics.
  Location only when you ask for "Your location", rounded to about 10 km for its town name. Nothing
  is sold, and there is no ad tracking in the apps (AdSense is off there). Everything is encrypted in
  transit. Accounts can be deleted in the app (Account settings → Delete account) and by email.
- **Store graphics**, generated by `npm run assets` in `apps/mobile`: `apps/mobile/store/play-icon-512.png`,
  `play-feature-1024x500.png` and `app-store-icon-1024.png`. Screenshots are yours to take (§1.5, §2.6).

## 1. Google Play

1. **(once) Developer account:** play.google.com/console, a one-time $25 fee, with identity
   verification. A *personal* account created since November 2023 must run a closed test with at
   least 12 testers for 14 days in a row before it can publish to production. Start that early.
   An organization account skips it, but needs a D-U-N-S number.
2. **(once) Upload key.** You keep this one; Google re-signs the app for the store (Play App Signing).
   ```bash
   mkdir -p ~/.config/takip && cd ~/.config/takip
   keytool -genkeypair -v -keystore android-upload.jks -alias takip -keyalg RSA -keysize 4096 -validity 10000 -dname "CN=TAKIP"
   cat > android-signing.properties <<EOF
   storeFile=$HOME/.config/takip/android-upload.jks
   storePassword=<the password you chose>
   keyAlias=takip
   keyPassword=<the same password>
   EOF
   chmod 600 android-upload.jks android-signing.properties
   ```
   Back up both files somewhere safe (a password manager). If the upload key is lost, Play can reset
   it, but the APK on takip.dev is signed with it too, and its users could only update by reinstalling.
   The Gradle build reads `~/.config/takip/android-signing.properties` by itself.
3. **Build:** `cd apps/mobile && npm ci && npm run android:release`. This gives the Play bundle
   (`android/app/build/outputs/bundle/release/app-release.aab`) and the APK for takip.dev
   (`…/apk/release/app-release.apk`). Or tag a release and take both from CI (§6).
4. **(once) Create the app** in Play Console: name TAKIP, default language English (US), App, Free.
   Category: *Maps & Navigation*. Choosing *News & Magazines* would also bring Play's news-app
   declaration with it.
5. **(once) Store listing:**
   - short description, up to 80 characters: *The world live on one map: flights, ships, satellites, cameras, weather.*
   - full description, up to 4,000 characters: the about page (takip.dev/about) is a good source;
   - the icon and feature graphic from §0;
   - at least 2 phone screenshots (portrait, 1080×2400 works). From an emulator or a phone:
     `adb exec-out screencap -p > shot.png`. Add 7" and 10" tablet screenshots to be listed for tablets.
6. **(once) App content:** privacy policy `https://takip.dev/privacy`. Ads: *No* (the apps show
   none). App access: everything works without signing in. Content rating: the IARC questionnaire,
   answered as a reference and news map. Target audience: 13+ or 18+. Data safety: §0.
   Account deletion URL: `https://takip.dev/?account=settings`.
7. **Testing, then production:** upload the `.aab` to *Internal testing* first. It reaches up to 100
   testers within minutes, and Play's pre-launch report adds screenshots from real devices. Then
   *Closed testing* (the 12 testers for 14 days, if §1.1 applies). Then *Production* → Create release
   → upload → Review. Reviews take from hours to a few days.
8. **(once) Links open the app:** in Play Console → Test and release → App integrity → App signing,
   copy both SHA-256 fingerprints: the app signing key and the upload key. On the NUC, add them to
   `~/takip/.env.local` as `ANDROID_CERT_SHA256=<signing>,<upload>`, then
   `systemctl --user restart takip-web`. Check https://takip.dev/.well-known/assetlinks.json.
9. **(once) Store link on the site:** `PLAY_STORE_URL=https://play.google.com/store/apps/details?id=dev.takip.app`
   in the NUC's `.env.local`, then restart takip-web. /download shows the Google Play button.

## 2. App Store (iPhone and iPad)

1. **(once) Xcode 26** from the Mac App Store, then:
   ```bash
   sudo xcode-select -s /Applications/Xcode.app
   xcodebuild -runFirstLaunch
   xcodebuild -downloadPlatform iOS          # the simulator runtime
   ```
   First build, no signing needed: `cd apps/mobile && npm ci && npm run ios:build`. Then
   `npm run ios:open`, choose an iPhone simulator and press ⌘R to see it run.
2. **(once) Apple Developer Program:** developer.apple.com/programs, $99 a year (see §0 on the seller name).
   The same membership signs and notarizes the Mac app (§3).
3. **(once) Sign in with Apple.** It is required (App Store rule 4.8) because the site offers Google
   and GitHub. Until it is set up, the iPhone app shows email sign-in only, so the app passes review
   without it. To add it:
   - Certificates, Identifiers & Profiles → Identifiers → the App ID `dev.takip.app` (made in step 4)
     → enable *Sign in with Apple*;
   - Identifiers → **Services ID** `dev.takip.web` → Sign in with Apple → domain `takip.dev`, return
     URL `https://takip.dev/api/auth/callback/apple`;
   - Keys → a key with Sign in with Apple → download the `.p8` and note the Key ID;
   - Better Auth wants the client secret as a signed JWT (ES256, at most six months, so put a
     reminder in the calendar); its Apple provider docs show how to make it. Then set
     `APPLE_CLIENT_ID=dev.takip.web` and `APPLE_CLIENT_SECRET=<jwt>` in the NUC's `.env.local` and
     restart takip-api. "Apple" then appears in sign-in everywhere, and the iPhone app shows all providers.
4. **(once) App Store Connect** (appstoreconnect.apple.com) → Apps → + → New App: iOS, name TAKIP
   (it must be unused on the store; otherwise *TAKIP: Live World Map*), primary language, bundle ID
   `dev.takip.app` (registered there if Xcode hasn't already), SKU `takip-ios`.
5. **(once) Signing in Xcode:** the App target and the TAKIPWidget target → Signing & Capabilities → choose
   your Team (automatic signing registers `dev.takip.app.widget` too). For takip.dev links to open the app: + Capability → Associated Domains →
   `applinks:takip.dev`. Then set `APPLE_TEAM_ID=<team id>` on the NUC and restart takip-web, and
   check https://takip.dev/.well-known/apple-app-site-association.
6. **Listing:** subtitle (30 characters), description, keywords (100 characters; e.g. *flight tracker,
   ship tracker, satellite, live map, earthquakes, webcams, weather radar, news map*), support URL
   `https://takip.dev/contact`, privacy policy `https://takip.dev/privacy`, category *Navigation*
   (second: *News* or *Reference*). Screenshots: 6.9" iPhone (1320×2868) is required. The app also
   runs on iPad, so 13" iPad shots (2064×2752) are required too; to skip them, make it iPhone-only by
   setting `TARGETED_DEVICE_FAMILY = 1` in Xcode → General → Supported Destinations.
   Simulator shots: `xcrun simctl io booted screenshot shot.png`.
   Age rating: no unrestricted web access (links leave for Safari). Live news and cameras may show
   real-world events, so answer the violence and mature-themes questions as *infrequent/mild*.
   App Privacy: §0.
7. **Upload:** Xcode → Product → Archive → Distribute App → App Store Connect → Upload. Or tag a
   release and let CI upload it (§5). The build shows up in TestFlight after processing (10–30 minutes).
8. **TestFlight, then review:** internal testers (up to 100) can install at once. To submit: the
   version page → Build → choose it → *Add for Review*. **Review notes** matter, because Apple turns
   down apps that are "just a website" (rule 4.2). For example:
   > TAKIP is a live map of public data (flights, ships, satellites, earthquakes, weather, cameras).
   > The app adds native sign-in through the system browser (Google, GitHub, Apple), location for
   > "near me" views, voice input for the TI assistant, links from takip.dev that open in the app,
   > and an offline screen. No account is needed to review; every feature works signed out.

   If it is still turned down under 4.2, the usual next step is a native feature people come back
   for: push notifications for watched areas (roadmap §1.10).
9. **(once) Store link on the site:** `APP_STORE_URL=https://apps.apple.com/app/id<number>` in the
   NUC's `.env.local`, then restart takip-web.

## 3. Desktop (no store needed)

- **macOS:** without signing, the `.dmg` is ad-hoc signed, and macOS refuses it until the user
  chooses *Open Anyway* (System Settings → Privacy & Security); /download says so. To sign and notarize:
  1. developer.apple.com → Certificates → + → **Developer ID Application**; install it, then export
     it from Keychain Access as a `.p12` with a password;
  2. appleid.apple.com → Sign-In and Security → App-Specific Passwords → make one for "TAKIP notarize";
  3. Locally: `CSC_LINK=~/path/cert.p12 CSC_KEY_PASSWORD=… APPLE_ID=you@… APPLE_APP_SPECIFIC_PASSWORD=… APPLE_TEAM_ID=… npm run dist:mac`
     in `apps/desktop`. In CI: the secrets in §5.
  4. Publish with `--signed macos` (§6), and the page drops the warning.
- **Windows:** unsigned, SmartScreen warns ("More info → Run anyway"). Code-signing certificates now
  live on hardware tokens, which CI can't use; the practical route is **Azure Trusted Signing**
  (about $10 a month, an Azure account, identity validation). electron-builder supports it through
  `win.azureSignOptions` in `apps/desktop/electron-builder.js`. Or list the app in the Microsoft
  Store, which is free for individuals and signs it. Either is optional.
- **Linux:** nothing to sign. Flathub and the Snap Store are optional later.

## 4. Direct downloads on takip.dev

```bash
node tools/native/publish.mjs collect --release apps-v1.0.0 [--signed macos,windows]
node tools/native/publish.mjs push
```
`collect` takes CI's draft release (or, without `--release`, this machine's builds: `apps/desktop/dist`
and the release APK), checks each file, writes `data/downloads/latest.json` and drops older builds.
It refuses to replace a published file with different contents under the same name (caches keep a
file for an hour); bump the version instead, or pass `--replace` if nobody has downloaded it yet.
`push` copies the folder to `~/takip/data/downloads` on the NUC; /download reads it on the next request.
No deploy is needed.

## 5. CI secrets

`gh secret set <NAME> --repo batuhantoker/takip-private`. The signing secrets, the signed builds and their releases
live on the private repo; the public `batuhantoker/takip` has none.
Missing secrets just mean unsigned builds, except that an Android release needs its key.

| Secret | Value |
|---|---|
| `ANDROID_KEYSTORE_BASE64` | `base64 -i ~/.config/takip/android-upload.jks` |
| `ANDROID_KEYSTORE_PASSWORD`, `ANDROID_KEY_ALIAS`, `ANDROID_KEY_PASSWORD` | from §1.2 (alias `takip`) |
| `APPLE_TEAM_ID` | Membership details → Team ID |
| `ASC_KEY_ID`, `ASC_ISSUER_ID`, `ASC_KEY_P8_BASE64` | App Store Connect → Users and Access → Integrations → App Store Connect API → a *Team key* with the App Manager role; `base64 -i AuthKey_XXXX.p8` |
| `MAC_CSC_LINK`, `MAC_CSC_KEY_PASSWORD` | `base64 -i DeveloperID.p12`, and its password |
| `APPLE_ID`, `APPLE_APP_SPECIFIC_PASSWORD` | for notarization (§3) |
| `WIN_CSC_LINK`, `WIN_CSC_KEY_PASSWORD` | a `.pfx` certificate, if you get one |

## 6. Each release

1. Bump the version in `apps/mobile/package.json` and `apps/desktop/package.json` (both the same), then
   `cd apps/mobile && npm run sync` and commit.
2. Tag and push: `git tag apps-v1.1.0 && git push origin apps-v1.1.0`. CI builds and signs everything,
   uploads the iPhone build to TestFlight and drafts a GitHub release with the files.
3. Review the draft. Try the APK and the desktop files on a machine.
4. Google Play: Production (or a testing track) → Create release → upload `TAKIP-<v>-android.aab` from
   the release. App Store: the version page → choose the new TestFlight build → submit.
5. takip.dev: `node tools/native/publish.mjs collect --release apps-v1.1.0 … && node tools/native/publish.mjs push`.
6. Publish the GitHub draft, or delete it; it is only the hand-off.
